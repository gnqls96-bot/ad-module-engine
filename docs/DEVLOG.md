| 카테고리 | 영상 | 이미지 | 영상 길이 (최소~최대, 평균) | 영상 비율 |

### 만든 것

- `ame reference ingest <폴더>` (`src/core/ingest.ts`, `src/cli/index.ts`)
  - 하위 폴더 이름 → `category` 태그, 전부 `efficiency=high`(고효율). 게재 일수는 비움 → 모든 레퍼런스가 같은 가중치
  - 분류 체계 기본값에 `카테고리`(값 없음, 폴더 이름 그대로)와 `효율`(고효율) 축 추가 — 업종은 코드에 넣지 않음
  - 영상: Whisper 받아쓰기 → 등록(관리자 = 공통) → `transcript.json` (단어마다 시작·끝 초, 확신도)
  - 이미지: 등록만 (화면 글자 읽기는 다음 기능)
  - 중복: 파일 내용 지문(SHA-256) 기준. 이름이 달라도 같은 내용이면 건너뜀. `reference add --file`에도 적용
  - 원본 파일은 건드리지 않음. 작업 공간에 `references/common/<지문 16자리>/<원래 이름>`으로 복사
  - 클라우드 전용 파일 확인: 맥 iCloud는 디스크 블록 0 또는 `.이름.icloud` 자리표시 파일 → 건너뛰고 "지금 다운로드" 안내. 윈도우는 이 방법으로 알 수 없어 로컬로 봄
  - 받아쓰기 이상 감지 (`transcriptIssues`): 소리 트랙 없음, 5초 미만, 받아쓰기 비어 있음, 초당 1.5글자 미만, 평균 확신도 0.5 미만, 같은 말 반복, Whisper가 지어내는 전형 문구, 말소리가 앞쪽에만 있음
- 작업 공간: `~/ame-workspace` (엔진 저장소 **밖**), 관리자 계정 이후빈
- `.gitignore`: `references/`, `transcript.json`, 영상·이미지·음성 확장자 전부 (docs/ 그림만 예외)

### 결정과 이유

| 결정 | 이유 |
| --- | --- |
| 복사본도 원래 이름 유지, 지문 폴더로 구분 | "원본 이름 그대로" 요청. 같은 이름의 다른 파일이 와도 섞이지 않음. 기존 `시각_이름` 방식은 이름이 바뀌어서 변경 |
| 받아쓰기 실패 시 등록하지 않음 | 다시 실행하면 그 파일만 다시 시도됨 (중복 검사에 안 걸림) |
| 받아쓰기 원문은 DB가 아니라 파일 옆 `transcript.json` | 단어 시간까지 넣으면 DB 파일이 커짐. DB에는 전체 문장만 |
| 작업 공간을 저장소 밖에 | `.gitignore`가 바뀌어도 타사 광고 원본이 실수로 올라갈 일이 없음 |

### 문제와 해결

- **한글이 깨짐** ("커��", "플� ��오"): Whisper는 한글 한 글자를 토큰 두 개로 쪼개는 경우가 있고, 토큰 단위로 읽으면 조각난 글자가 버려짐.
  → 단어 단위로 끊어 받기(`splitOnWord`). 단어 묶음은 글자가 온전함. 시간은 단어 시작·끝.
  → ⚠ 기존 `module align`(촬영본 자막 맞춤)은 아직 토큰 단위라 같은 문제가 있음. 자막 글자는 대본 원문을 쓰므로 화면에는 안 보이지만, 깨진 글자 부분은 시간이 보간됨. 다음에 같은 방식으로 바꿀 것.

## 2026-10-29 오후 · 맥·윈도우 공통 (v0.3.0)

### 목표

맥이 아니어도 (회사·개인 윈도우 PC) 같은 명령으로 전부 동작하게.

### 점검 결과와 고친 것

| 항목 | 문제 | 해결 |
| --- | --- | --- |
| 내장 음성 | `macos-say`는 맥 전용 | 윈도우 내장 음성 `windows-tts` 추가 (PowerShell System.Speech). 대본·경로는 환경 변수로 넘겨 따옴표 문제 회피. 목소리를 안 정하면 설치된 한국어 목소리 자동 선택, 없으면 설치 방법 안내 |
| Whisper 설치 확인 | 실행 파일 이름을 `whisper-cli`로만 찾아 윈도우(`.exe`)에서는 항상 "미설치" | 운영체제별 경로. 윈도우 배포 zip이 다른 폴더에 풀리면 실행 파일·DLL을 `build/bin`으로 모음 |
| Whisper 모델 | 다운로드가 끊기면 빈 파일이 남아 "설치됨"으로 착각 → 실행 시 "bad magic" 오류 (개발 서버에서 실제로 발생) | 실패 시 반쪽 파일 삭제, 파일 크기·ggml 머리글로 정상 여부 확인 |
| 모델 크기 | 고정 (large-v3-turbo) | `setup-whisper --model small` 등 선택, 고른 모델을 기억 (`config.json`) |
| 데모 | bash 스크립트라 윈도우 기본 터미널에서 실행 불가 | Node 스크립트(`scripts/demo.mjs`)로 교체. `--quick`, `--no-render`, `--voice`, `--workspace` |
| 파일 교체 | 윈도우는 백신·색인이 파일을 잡고 있으면 교체 실패 가능 | 데이터 저장 시 짧게 재시도 |
| 다른 드라이브로 이동 | 이름 바꾸기로는 D: → C: 이동 불가 | 실패하면 복사 후 삭제 |
| 파이썬 이름 | 윈도우는 `python` | 운영체제별 기본값 (`AME_PYTHON`으로 지정 가능) |
| 줄바꿈 | 윈도우 Git이 CRLF로 바꿀 수 있음 | `.gitattributes`로 LF 고정 |
| 실패 보고 | `module voice/align`이 일부 실패해도 성공으로 끝남 | 실패가 있으면 종료 코드 1 |

### 검증 방법: 자동 점검 (GitHub Actions)

윈도우 PC가 없어도 확인할 수 있도록, push할 때마다 **맥·윈도우·리눅스 실제 머신**에서 아래를 자동 실행:

1. 타입 검사 + 단위 테스트
2. 데모 전체 흐름 + 실제 렌더링 (`--quick`: 9:16 1편 + 내레이션 버전 1편), 영상 2편 이상 나왔는지 확인
3. Whisper 설치 (가장 작은 tiny 모델) → 그 운영체제의 내장 음성으로 문장 읽기 → 영상으로 만들어 모듈 등록 → `module align` → 자막 출처가 `aligned`이고 시간이 음성 범위 안인지 확인 (`scripts/ci-voice-check.mjs`)
4. 렌더링된 영상은 7일간 다운로드 가능 (Actions → 실행 → Artifacts)

자동 점검 서버에는 한국어 목소리가 없어서 3번은 영어 문장으로 확인합니다. 한국어 품질은 실제 PC에서 `ame voice sample`로 확인.

### 자동 점검으로 찾은 문제

- **맥 Homebrew의 FFmpeg에는 글자 그리기 필터(drawtext)가 없음** → 더미 클립 생성이 맥에서만 실패. 맥북에서도 똑같이 막혔을 문제.
  → FFmpeg에 drawtext가 있는지 먼저 확인하고, 없으면 라벨 없이 색 화면으로 만들도록 변경. 실제 광고 자막은 Remotion 템플릿(브라우저 글꼴)이 그리므로 결과물에는 영향 없음.
- 결과 영상 보관 단계가 `..` 경로를 받지 않음 → 작업 폴더를 실행기 임시 폴더로 옮김.
- 실패한 단계의 마지막 60줄을 오류 표시(annotation)로 남기도록 `scripts/ci-run.mjs` 추가 (실행 기록 전체를 못 여는 환경에서도 원인 확인 가능).

이 개발 서버에서 확인한 것: 타입 검사, 테스트 24개, `demo.mjs --no-render`, 리눅스 음성(flite) → 모듈 등록까지. 모델 다운로드가 막힌 환경이라 Whisper 실행은 자동 점검 결과로 확인.

## 2026-10-29 오후 · 1.5단계 음성 (v0.2.0)

### 목표

모듈 대사 → TTS 내레이션, 그리고 **실제 말하는 시점에 맞춘 자막**. 무료로 시작하고, 품질이 아쉬우면 설정 한 줄로 유료(일레븐랩스)로 바꿀 수 있게.

### 결정

| 결정 | 내용 | 이유 |
| --- | --- | --- |
| 제공자 교체 구조 | `TtsProvider` 인터페이스 하나에 무료(melotts, macos-say) · 무료 한도(google, azure) · 유료(elevenlabs) · 시험용(mock) | 품질 비교 후 브랜드별로 `ame voice set` 한 줄로 전환 |
| 기본값 `auto` | 쓸 수 있는 무료 제공자를 구글 → 애저 → MeloTTS → 맥 내장 순서로 선택. 유료는 자동 선택 안 함 | 모르는 사이 과금되는 일 방지 |
| 자막 타이밍 통일 | 어떤 TTS든 "음성 파일 → Whisper(무료, 내 맥) → 시간" 한 방식. TTS가 타이밍을 직접 주면(일레븐랩스) 그걸 사용 | TTS를 바꿔도 자막 쪽은 손대지 않음. 촬영본 자막에도 같은 방식 |
| 자막 글자 = 대본 원문 | 받아쓰기 결과에서는 시간만 가져오고, 대본과 받아쓰기를 글자 단위 최장 공통 부분열(LCS)로 짝지음 | Whisper 오인식("세 방울"→"3방울")이 자막에 들어가지 않게 |
| API 키 | 환경 변수로만. DB·저장소에 저장 안 함 | 보안, 회사 계정 키를 개인 저장소에 남기지 않기 |
| 음량 | 모든 제공자 결과를 48kHz AAC, -16 LUFS로 정규화 | 제공자를 바꿔도 소재 간 음량 차이 없게 |

### 만든 것

- `src/voice/providers.ts`: 6개 제공자, `resolveProvider('auto')`, 음량 정규화
- `src/voice/whisper.ts`: whisper.cpp 설치·모델 다운로드(`ame voice setup-whisper`), 한국어 단어 단위 받아쓰기 (기본 모델 large-v3-turbo)
- `src/voice/align.ts`: 단어 시간 → 글자 시간, 대본 ↔ 받아쓰기 LCS 짝짓기, 못 짝지은 글자 보간, 자막 구간 생성, 추정 자막
- `src/voice/service.ts`: 모듈 내레이션 생성(`module voice`), 촬영본 자막 맞춤(`module align`)
- 데이터: 모듈에 `voiceover`(파일·제공자·목소리·길이·만든 대사), `captions`(구간·출처: provider/aligned/estimated)
- 템플릿: 내레이션 재생, 원래 영상 소리 15%로 낮춤, 음성 맞춤 자막, **내레이션이 영상보다 길면 마지막 장면 정지**
- 조합 길이 검사: 내레이션까지 포함한 실제 길이(`effectiveDuration`)로 계산
- 명령: `voice providers / set / sample / setup-whisper`, `module voice`, `module align`
- 테스트 9개 추가 (총 24개)

| 받아쓰기가 대본과 달라도 자막은 대본 원문, 시간은 실제 발화 시점 | ✅ 단위 테스트: 띄어쓰기·숫자 표기·오인식이 섞인 받아쓰기로 확인. 문장 사이 쉼(3.0~3.5초) 뒤에 다음 자막 시작 |
| 내레이션 → 렌더링 | ✅ 시험용 음성(mock)으로 4개 모듈 내레이션 → 15.4초 영상, 영상+음성 트랙, 자막이 음성 구간에 맞춰 바뀜 |
| 내레이션이 영상보다 길 때 | ✅ 경고 + 마지막 장면 정지, 조합 길이 15.0 → 15.4초로 재계산 |
| whisper.cpp 설치 | ✅ 이 작업 공간에서 1.7.6 빌드 성공 (`whisper-cli`) |
| Whisper 모델·MeloTTS 모델 다운로드, 실제 한국어 음성 품질 | ⏳ 개발 서버에서 모델 사이트 접속이 막혀 있어 맥북에서 확인 필요 |
| 구글·애저·일레븐랩스 실제 호출 | ⏳ API 키가 필요해 맥북에서 확인 필요. 요청 형식은 각 공식 문서 기준으로 작성 |

### 문제와 해결

1. **다른 배치에서 같은 조합의 소재 코드가 겹침** (`..._v1`이 이미 있다고 새 렌더링을 건너뜀). 내레이션 버전은 다른 영상인데 같은 이름이 되는 문제.
   → 소재 코드는 작업 공간 전체에서 유일하게: 이미 쓰인 코드면 다음 빈 버전 번호 사용(`_v4`). 실패한 작업의 코드는 재사용 가능. 중복 판단은 "같은 배치·조합·비율·배치 버전" 기준. 테스트 추가.
2. **자막 줄바꿈이 "세 / 방울만"처럼 한 글자 단어를 줄 끝에 남김**.
   → 줄 끝에 한 글자 단어가 오는 위치는 피하도록 점수 조정 ("토너로 결을 정돈하고 / 세 방울만 눌러 바르세요."). 테스트 추가.
3. **"음성이 영상보다 길어요" 경고가 실제로는 음성이 더 짧은데도 뜸** (끝 여유 0.25초 때문).
   → 실제로 늘어나는 시간을 계산해 0.05초 넘을 때만, 몇 초 멈추는지와 함께 표시.
4. 다양성 경고 문구 조사 오류("후킹 유형가") → "후킹 유형: 전부 '상식반전' 한 종류" 형식으로 수정.

### 계정·공개 범위 규칙 (사용자 요청 반영)

- 관리자가 등록한 레퍼런스·모듈·배치 = **공통** → 모든 팀원에게 적용
- 팀원이 등록한 것 = **개인** → 본인만 보고, 본인 생성에만 적용. 다른 팀원은 못 봄
- 관리자는 모든 팀원 데이터를 보고, 생성에 공통 + 모든 팀원 레퍼런스가 적용됨
- 관리자는 관리자 계정을 언제든 추가 발급 (팀장·본부장용)
- 추가로 넣은 것: 레퍼런스뿐 아니라 모듈·배치·결과물에도 같은 규칙 / 관리자의 "공통으로 올리기"(원 소유자 기록 유지)
- 구현: `src/core/access.ts` (`canSee`, `appliedForGeneration`, `defaultScope`, `promoteToCommon`)

### 만든 것

- **데이터 구조** (`types.ts`): 조직 → 브랜드 → 제품 → 모듈 / 레퍼런스 / 배치 → 조합 → 렌더 작업, 작업 기록(audit). 모든 레코드에 `ownerId`·`scope`

- **모듈 등록** (`modules.ts`, `media.ts`): ffprobe로 길이·해상도·프레임·음성 확인 → 규격 검사(실패는 등록 거부, 경고는 기록) → 종류별 코드(`H001`) 부여 → 파일명 정리 → 규칙 팩 검사(차단 표현이면 자동 반려). 폴더 스캔 일괄 등록, 옆의 `.meta.json`에서 대사·태그 읽기

### 문제와 해결

1. **Remotion 렌더용 Chrome 자동 다운로드가 막힘** (개발 서버의 네트워크 제한).
   → 이미 설치된 Chrome 렌더러를 찾아 쓰도록 `browserExecutable()` 추가. 맥북에서는 Remotion이 자동으로 내려받으므로 신경 쓸 필요 없음. 직접 지정은 `AME_BROWSER`.
2. **가격만 바꾸면 할인율이 옛날 값으로 남음** (39,000 → 29,000원인데 34% 그대로).
   → `mergeOffer()`: 가격이나 정가가 바뀌고 할인율을 직접 주지 않았으면 다시 계산. 테스트 추가.
3. **렌더링이 느림** (15초 영상 1편에 약 130초, 2코어 서버).
   → 원본과 출력 비율이 같으면 흐린 배경 레이어를 그리지 않게 변경 (영상 디코딩이 절반). 9:16: **131.6초 → 42.3초**. 4:5는 흐림 강도를 낮춰 102초 → 88초. 맥북 M1 Pro(10코어)에서는 더 빠를 것으로 예상.
4. **작업자가 강제 종료되면 작업이 "진행 중"으로 남음**.
   → 작업자 ID에 컴퓨터 이름과 프로세스 번호를 넣고, 같은 컴퓨터의 죽은 프로세스 작업은 다음 실행 때 바로 대기열로 복구. 다른 컴퓨터 작업은 30분 후 복구.
5. **모듈 코드 순서가 파일 이름순**이라 더미 세트 순서와 다름 (`hook_acne-pain`이 H001).
   → 동작에는 문제 없음. 폴더 스캔은 파일 이름순으로 번호를 매긴다는 점을 기록해 둠.

### 남은 것 / 알려진 한계

- 자막 타이밍은 글자 수 비례 근사. 2단계에서 받아쓰기(단어 타임스탬프)로 교체

- Remotion 회사 라이선스는 도입 회사에서 확인 필요
