## 2026-10-29 오후 · 1.5단계 음성 (v0.2.0)

### 목표

모듈 대사 → TTS 내레이션, 그리고 **실제 말하는 시점에 맞춘 자막**. 무료로 시작하고, 품질이 아쉬우면 설정 한 줄로 유료(일레븐랩스)로 바꿀 수 있게.

### 결정

| 결정 | 내용 | 이유 |
| --- | --- | --- |
| 제공자 교체 구조 | `TtsProvider` 인터페이스 하나에 무료(melotts, macos-say) · 무료 한도(google, azure) · 유료(elevenlabs) · 시험용(mock) | 품질 비교 후 브랜드별로 `ame voice set` 한 줄로 전환 |
| 기본값 `auto` | 쓸 수 있는 무료 제공자를 구글 → 애저 → MeloTTS → 맥 내장 순서로 선택. 유료는 자동 선택 안 함 | 모르는 사이 과금되는 일 방지 |
| 자막 타이밍 통일 | 어떤 TTS든 "음성 파일 → Whisper(무료, 내 맥) → 시간" 한 방식. TTS가 타이밍을 직접 주면(일레븐랩스) 그걸 사용 | TTS를 바꿔도 자막 쪽은 손대지 않음. 촬영본 자막에도 같은 방식 |
| 자막 글자 = 대본 원문 | 받아쓰기 결과에서는 시간만 가져오고, 대본과 받아쓰기를 글자 단위 최장 공통 부분열(LCS)로 짝지음 | Whisper 오인식("세 방울"→"3방울")이 자막에 들어가지 않게 |
| API 키 | 환경 변수로만. DB·저장소에 저장 안 함 | 보안, 회사 계정 키를 개인 저장소에 남기지 않기 |
| 음량 | 모든 제공자 결과를 48kHz AAC, -16 LUFS로 정규화 | 제공자를 바꿔도 소재 간 음량 차이 없게 |

### 만든 것

- `src/voice/providers.ts`: 6개 제공자, `resolveProvider('auto')`, 음량 정규화
- `src/voice/whisper.ts`: whisper.cpp 설치·모델 다운로드(`ame voice setup-whisper`), 한국어 단어 단위 받아쓰기 (기본 모델 large-v3-turbo)
- `src/voice/align.ts`: 단어 시간 → 글자 시간, 대본 ↔ 받아쓰기 LCS 짝짓기, 못 짝지은 글자 보간, 자막 구간 생성, 추정 자막
- `src/voice/service.ts`: 모듈 내레이션 생성(`module voice`), 촬영본 자막 맞춤(`module align`)
- 데이터: 모듈에 `voiceover`(파일·제공자·목소리·길이·만든 대사), `captions`(구간·출처: provider/aligned/estimated)
- 템플릿: 내레이션 재생, 원래 영상 소리 15%로 낮춤, 음성 맞춤 자막, **내레이션이 영상보다 길면 마지막 장면 정지**
- 조합 길이 검사: 내레이션까지 포함한 실제 길이(`effectiveDuration`)로 계산
- 명령: `voice providers / set / sample / setup-whisper`, `module voice`, `module align`
- 테스트 9개 추가 (총 24개)

### 확인한 것

| 항목 | 결과 |
| --- | --- |
| 받아쓰기가 대본과 달라도 자막은 대본 원문, 시간은 실제 발화 시점 | ✅ 단위 테스트: 띄어쓰기·숫자 표기·오인식이 섞인 받아쓰기로 확인. 문장 사이 쉼(3.0~3.5초) 뒤에 다음 자막 시작 |
| 내레이션 → 렌더링 | ✅ 시험용 음성(mock)으로 4개 모듈 내레이션 → 15.4초 영상, 영상+음성 트랙, 자막이 음성 구간에 맞춰 바뀜 |
| 내레이션이 영상보다 길 때 | ✅ 경고 + 마지막 장면 정지, 조합 길이 15.0 → 15.4초로 재계산 |
| whisper.cpp 설치 | ✅ 이 작업 공간에서 1.7.6 빌드 성공 (`whisper-cli`) |
| Whisper 모델·MeloTTS 모델 다운로드, 실제 한국어 음성 품질 | ⏳ 개발 서버에서 모델 사이트 접속이 막혀 있어 맥북에서 확인 필요 |
| 구글·애저·일레븐랩스 실제 호출 | ⏳ API 키가 필요해 맥북에서 확인 필요. 요청 형식은 각 공식 문서 기준으로 작성 |

### 문제와 해결

1. **다른 배치에서 같은 조합의 소재 코드가 겹침** (`..._v1`이 이미 있다고 새 렌더링을 건너뜀). 내레이션 버전은 다른 영상인데 같은 이름이 되는 문제.
   → 소재 코드는 작업 공간 전체에서 유일하게: 이미 쓰인 코드면 다음 빈 버전 번호 사용(`_v4`). 실패한 작업의 코드는 재사용 가능. 중복 판단은 "같은 배치·조합·비율·배치 버전" 기준. 테스트 추가.
2. **자막 줄바꿈이 "세 / 방울만"처럼 한 글자 단어를 줄 끝에 남김**.
   → 줄 끝에 한 글자 단어가 오는 위치는 피하도록 점수 조정 ("토너로 결을 정돈하고 / 세 방울만 눌러 바르세요."). 테스트 추가.
3. **"음성이 영상보다 길어요" 경고가 실제로는 음성이 더 짧은데도 뜸** (끝 여유 0.25초 때문).
   → 실제로 늘어나는 시간을 계산해 0.05초 넘을 때만, 몇 초 멈추는지와 함께 표시.
4. 다양성 경고 문구 조사 오류("후킹 유형가") → "후킹 유형: 전부 '상식반전' 한 종류" 형식으로 수정.

## 2026-10-29 · 1단계 뼈대 (v0.1.0)

### 목표

실제 영상 없이 더미 클립만으로 "모듈 등록 → 조합 생성 → 검사 → 렌더링 → 소재 코드로 저장 → 조합 목록 출력"이 끝까지 돌아가는 상태.
지금 회사 자산과 계정은 쓰지 않는다 (더미 클립, 가상 브랜드 `DEMO / 글로우 세럼`, 개인 GitHub).

### 확정한 설계 결정

| 결정 | 내용 | 이유 |
| --- | --- | --- |
| 사용 방식 | 엔진 하나 + 사용 창구 두 개 (Claude 스킬, 웹 화면은 3단계) | 혼자는 말로 빠르게, 팀은 화면으로. 결과물은 같은 엔진이 만든다 |
| 저장 위치 | 작업 공간 폴더 하나에 데이터·영상 모두. 저장소 인터페이스(`Store`)로 분리 | 회사가 바뀌어도 폴더 위치(드라이브 동기화 등)만 바꾸면 됨. DB는 Supabase로 교체 예정 |
| 렌더링 | 처음부터 Remotion | 오퍼 데이터화·한글 자막·브릿지·비율 변형을 템플릿 하나로. 나중에 FFmpeg에서 갈아타는 비용 회피 |
| 사용자 범위 | 본부 단위 다수. 관리자 계정(여러 개) + 팀원 계정 | 팀원별 성과 분석, 상위 관리자 계정 추가 발급 요구 |
| 업종 | 업종 무관. 분류 체계·규칙 팩·브랜드 키트는 설정 파일 | 이직 후 어떤 브랜드를 맡을지 모름. 레퍼런스로 분류를 키움 |
| 언어 | TypeScript 하나로 통일 (`tsx`로 바로 실행, 빌드 단계 없음) | Remotion이 TS/React. 언어가 하나면 유지보수가 쉬움 |

### 계정·공개 범위 규칙 (사용자 요청 반영)

- 관리자가 등록한 레퍼런스·모듈·배치 = **공통** → 모든 팀원에게 적용
- 팀원이 등록한 것 = **개인** → 본인만 보고, 본인 생성에만 적용. 다른 팀원은 못 봄
- 관리자는 모든 팀원 데이터를 보고, 생성에 공통 + 모든 팀원 레퍼런스가 적용됨
- 관리자는 관리자 계정을 언제든 추가 발급 (팀장·본부장용)
- 추가로 넣은 것: 레퍼런스뿐 아니라 모듈·배치·결과물에도 같은 규칙 / 관리자의 "공통으로 올리기"(원 소유자 기록 유지)
- 구현: `src/core/access.ts` (`canSee`, `appliedForGeneration`, `defaultScope`, `promoteToCommon`)

### 만든 것

- **데이터 구조** (`types.ts`): 조직 → 브랜드 → 제품 → 모듈 / 레퍼런스 / 배치 → 조합 → 렌더 작업, 작업 기록(audit). 모든 레코드에 `ownerId`·`scope`

### 문제와 해결

1. **Remotion 렌더용 Chrome 자동 다운로드가 막힘** (개발 서버의 네트워크 제한).
   → 이미 설치된 Chrome 렌더러를 찾아 쓰도록 `browserExecutable()` 추가. 맥북에서는 Remotion이 자동으로 내려받으므로 신경 쓸 필요 없음. 직접 지정은 `AME_BROWSER`.
2. **가격만 바꾸면 할인율이 옛날 값으로 남음** (39,000 → 29,000원인데 34% 그대로).
   → `mergeOffer()`: 가격이나 정가가 바뀌고 할인율을 직접 주지 않았으면 다시 계산. 테스트 추가.
3. **렌더링이 느림** (15초 영상 1편에 약 130초, 2코어 서버).
   → 원본과 출력 비율이 같으면 흐린 배경 레이어를 그리지 않게 변경 (영상 디코딩이 절반). 9:16: **131.6초 → 42.3초**. 4:5는 흐림 강도를 낮춰 102초 → 88초. 맥북 M1 Pro(10코어)에서는 더 빠를 것으로 예상.
4. **작업자가 강제 종료되면 작업이 "진행 중"으로 남음**.
   → 작업자 ID에 컴퓨터 이름과 프로세스 번호를 넣고, 같은 컴퓨터의 죽은 프로세스 작업은 다음 실행 때 바로 대기열로 복구. 다른 컴퓨터 작업은 30분 후 복구.
5. **모듈 코드 순서가 파일 이름순**이라 더미 세트 순서와 다름 (`hook_acne-pain`이 H001).
   → 동작에는 문제 없음. 폴더 스캔은 파일 이름순으로 번호를 매긴다는 점을 기록해 둠.

### 남은 것 / 알려진 한계

- 자막 타이밍은 글자 수 비례 근사. 2단계에서 받아쓰기(단어 타임스탬프)로 교체
- 렌더링 중 진행률은 25% 단위 로그만. 웹 화면에서 진행 바로
